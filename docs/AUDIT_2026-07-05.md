## 2. Findings (severity-ranked)

Status: **fixed** = corrected in this audit (commit listed) · **flagged** = known gap or
risk left for a decision / future phase.

### Critical

| # | Finding | Where | Status |
|---|---|---|---|
| C1 | **Rodin override glyph U+E103 never matched** — the relational override `f  {k↦v}` is stored as private-use codepoint U+E103 in raw `.bum` XML; `FN3-override` expected `⊴` or whitespace, so `start_tx` silently lost `pktFwdr[pkt] = x;`. The rules test was false-green because its pasted string had degraded the glyph to a space. U+E103 appears **56×** across the shdecom/RTMCS/MintRoute exports, so every future protocol hits this. | `src/engine/rules.ts` (FN3-override); `tests/rules.test.ts:63` | **fixed** `dcaf6c7` |
| C2 | **`type(pkt) ∈ CONTROL` silently dropped** — no rule matched `f(k) ∈ S`, so `creatingControlPacket` lost its packet-type guard (semantic weakening: any packet passed as control). | `src/engine/rules.ts`; visible in pre-fix `out/Pm3App.cc` | **fixed** `979bb26` (FN1∘SET1 rule) |
| C3 | **Silent-drop design** — `translateEvent` discarded any clause no rule matched, with no diagnostics; C1/C2 are exactly how that failure mode bites. | `src/engine/ruleEngine.ts:44-52` (pre-fix) | **fixed** `7b41cf9` — unmatched clauses now emit `// UNTRANSLATED GUARD/ACTION: <Event-B>` in the generated code |
| C4 | **Generated `.ned` referenced a nonexistent NED type** — INET 4.5 has no `RoutingProtocolBase.ned` (C++-only base), so `import inet.routing.base.RoutingProtocolBase; simple X extends …` failed NED resolution the moment the file entered a NED path. | `src/engine/codeEmitter.ts` (ned template) | **fixed** `a67b43c` — standalone `simple <Name> like IApp` + `socketIn`/`socketOut` gates + `@class`, mirroring `inet/routing/rip/Rip.ned`; validated with `opp_nedtool` |

### Important

| # | Finding | Where | Status |
|---|---|---|---|
| I1 | **1-to-N event-split flattening lost the ancestor body** — when ≥2 events refine the same abstract event, the first child's re-keying deleted the ancestor, so later siblings inherited nothing. Harmless for the current fixtures (uM2's split children are non-extended and restate everything) but guaranteed wrong for *extended* splits — precisely DSR's `reverse_path_init`/`reverse_path_loop` shape. | `src/engine/flattener.ts` | **fixed** `7276238` (+ regression test) |
| I2 | **Refines cycle → infinite loop** in `chain()` and `leafOf()` on malformed input. | `flattener.ts`, `pipeline.ts` | **fixed** `7276238` (clear error) |
| I3 | **Typing detector missed `ℤ/ℕ/𝔹`** — `data ∈ ℤ` was dropped by rule-miss fall-through, not by the ST4 typing rule (`(\w+)` can't capture ℤ). Would have produced false `// UNTRANSLATED` noise after C3's fix. | `src/engine/ruleEngine.ts:21` | **fixed** `eb19ea3` |
| I4 | **`M ≔ M ∪ {k↦v}` on a map-of-sets variable** emitted an ill-typed pair insert (asymmetric with `DIFF-pair`, which had the MS3 branch). Not exercised by current fixtures; would not compile if hit. | `src/engine/rules.ts` (UNION-pair) | **fixed** `979bb26` |
| I5 | **ENC1/ENC6 unreachable in the resolver** — `infer()` never returns `"int"` or `"bool"`; a scalar machine variable (`x ∈ ℕ`, `flag ∈ BOOL`) would encode as `"set"` (wrong type, wrong rule dispatch). No scalar machine variables exist in the shdecom pattern, and there is also no scalar-assignment rule (`x ≔ v`) — both belong to the protocol-specific machines (RTMCS M4–M6 counters etc.). | `src/engine/encodingResolver.ts` | **flagged** — implement together with the network-layer rule families |
| I6 | **Form 01 §6 over-claim risk** — the criterion says "compiles **and executes**"; the tool currently achieves *compiles* (syntax gate). Execution requires the hand-authored `handleMessageWhenUp` body + a hosting simulation. Repo docs (`README`, `compile-gate.md`, `OMNETPP_INTEGRATION.md`) state this accurately; **CLAUDE.md now carries the same honesty note** (2026-07-05 entry). Keep the distinction explicit in the Phase-5 report. | project docs | **fixed** (doc reconciliation) / execution itself **flagged** (Phase 4) |
